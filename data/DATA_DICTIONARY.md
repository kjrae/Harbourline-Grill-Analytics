# Data dictionary

A fictional 10-location casual-dining chain in the Lower Mainland, BC.
**Period:** Mon 2025-01-06 → Sun 2026-08-30 (86 full weeks) · **Hours:** 7:00–23:00 · closed Dec 25.
All data is **synthetic**, generated by `generate.py` (seed 29). Running it again produces identical files.

```
data/raw/    messy "source system" extracts: what the Snowflake pipeline loads
data/clean/  the same data as a clean star schema (the expected result of the pipeline)
```

In Snowflake, the cleaned tables live in the `CORE` schema with the same names in UPPERCASE
(the date column is `DIM_DATE[CALENDAR_DATE]`).

## 1. Clean tables (`clean/`)

### Dimensions
| Table | Grain | Key columns |
|---|---|---|
| `dim_location` | 1 row / restaurant | location_id, location_name, city, region, area_manager, latitude, longitude, seats, has_patio, open_date |
| `dim_date` | 1 row / day, 2025-01-05 → 2026-08-30 (starts a day early for the opening inventory count) | date, year, quarter, month_num, year_month, day_of_week, dow_num (Mon=1), is_weekend, week_start (Monday), holiday_name, is_stat_holiday, season |
| `dim_menu_item` | 1 row / item | menu_item_id, menu_item_name, category, is_main, price_2025, price_2026 (+4% from 2026-01-05) |
| `dim_ingredient` | 1 row / ingredient | ingredient_id, ingredient_name, ingredient_category, unit, std_cost_2025, std_cost_2026 (budget/standard cost), expected_waste_rate, is_produce, supplier |
| `dim_employee` | 1 row / employee | employee_id, employee_name, home_location_id, role, hourly_wage (2025 base), hire_date. Roster is mostly part-time: max 1 shift/day, max 5 shifts/week, avg ~25 h/week |
| `bridge_recipe` | item × ingredient | menu_item_id, ingredient_id, qty_per_item, unit — **the link between sales and food cost** |
| `dim_weather_daily` | 1 row / day | max_temp_c, precip_mm, is_rainy_day (≥2mm). synthetic |

### Facts
| Table | Grain | Measures |
|---|---|---|
| `fact_sales_item_daypart` | date × location × daypart × item | qty_sold, unit_price, gross_sales, discounts, comps, net_sales |
| `fact_covers_hourly` | date × location × hour | covers (guests), net_sales |
| `fact_labour_shifts` | 1 row / shift | role, shift_block (AM 7–15 / MID 11–19 / PM 15–23), scheduled_start/end, actual_start/end, scheduled_hours, actual_hours, hourly_wage (includes 2.5% raise from 2026-01-01), labour_cost (wages only, no payroll burden) |
| `fact_labour_hourly` | date × location × hour | labour_hours, labour_cost, covers, net_sales — **pre-built for the heatmap**. Hours 6 and 23 hold early clock-ins / late clock-outs only; filter the heatmap to hours 7–22 |
| `fact_purchases` | delivery line | delivery_date, ingredient_id, qty_received, unit, unit_cost, line_total, supplier |
| `fact_inventory_counts` | week-end count | count_date (Sunday), qty_on_hand. Opening count on 2025-01-05 |
| `fact_waste_log` | weekly log entry | qty_wasted, reason — what staff *recorded* |
| `fact_ingredient_price_weekly` | week × ingredient | market_unit_cost |
| `fact_ingredient_usage_weekly` | week × location × ingredient | theoretical_qty, actual_qty, recorded_waste_qty |
| `fact_targets_monthly` | month × location | net_sales_budget, labour_pct_target (30%), food_cost_pct_target (28.5%), avg_check_target |

**Dayparts:** Breakfast 7–11 · Lunch 11–15 · Afternoon 15–17 · Dinner 17–21 · Late Night 21–23.

**Key definitions**
- Theoretical usage = Σ(qty_sold × qty_per_item) — what you *should* have used
- Actual usage = opening count + purchases − closing count — what you *did* use
- Variance = actual − theoretical; recorded waste explains part of it; the rest is **unexplained** (over-portioning, unrecorded waste, theft)

## 3. Planted patterns (spoilers)

The generator builds these in on purpose, so the dashboard can be checked against a known answer.

1. **Coquitlam Centre (L06) Mondays — labour.** Labour % ≈ **43%** on Mondays vs 27–36% for every other store/weekday combination (other stores' Mondays top out ~35%). Root cause: Monday schedule is built off the *Friday* template (≈40% more staff than covers need), and unlike other stores, managers don't cut staff early when it's slow. Recommendation: rebuild the Monday template from forecast covers; ~$ savings = excess hours × avg wage.
2. **Guildford (L05) tomatoes — food cost.** From **2026-03-02**, actual tomato usage runs **~28% above theoretical** vs 4–8% everywhere else (and ~5% at Guildford itself before March), and recorded waste doesn't explain it → over-portioning (new cook? no portion scale?). Only visible when you drill location → ingredient (decomposition tree). Recommendation: portion spec training / pre-portioned tomato, weekly variance report.
3. **Winter tomato price spike.** Market price ~$6.30/kg in Feb 2025 → **~$9.50/kg in Feb 2026** (+~50% YoY), ~$4/kg in summer. Tomato is in 14 menu items, so it hits the burger line hardest. Shows up as *price variance* in the waterfall.
4. **Beef creep.** Beef patty cost runs ~+7.5%/yr vs a +5% budget → persistent price variance; squeezes burger margins even after the +4% menu increase.
5. **Menu engineering (mains, 2025 standard costs).** Harbour Classic Burger is the #1 seller (~15% of mains) but a **Plowhorse** (margin ~$11.23 vs weighted avg ~$13.50); the other burgers, Pancake Stack and Sunrise Breakfast Burger are Plowhorses too. Stars: Classic Breakfast, Eggs Benedict, Fish & Chips, Chicken Caesar, Clubhouse, Tenders. **Puzzles** (profitable, under-ordered): Sirloin Steak (high $ margin but 44% food cost), Salmon Bowl, Harvest Grain Bowl, Pasta Primavera. **Dogs:** Garden Veggie Burger, Veggie Hummus Wrap, Avocado Toast.
6. **Natural patterns:** weekend brunch spike, Mon–Tue slowest, summer peak (patio stores L01, L02, L07 get a bigger lift and a bigger rainy-day hit), 2026 same-store traffic +3%, Christmas Eve/NYE short days.

## 4. Planted data-quality issues (`raw/`)

|---|---|
| `pos_sales_extract.csv` | store names inconsistent (8% of rows: "KITS", "DT Robson", trailing spaces, CAPS); ~5% of dates as `04-Mar-2025`; ~3% item names upper-cased with trailing space; ~0.2% null net_sales; ~0.4% duplicate rows |
| `pos_covers_hourly_extract.csv` | store name variants |
| `timeclock_extract.csv` | role variants ("LINE COOK", "Cook - Line", "server"); ~0.5% missing actual_end (forgot to clock out); ~0.3% duplicate rows |
| `purchasing_extract.csv` | ~4% of produce lines in **lb** instead of kg (unit_cost per lb); supplier names sometimes CAPS; ~0.3% duplicates |
| `inventory_counts_extract.csv`, `waste_log_extract.csv` | store name variants |
| `ref_*.csv` | clean reference/master data (locations, menu, ingredients, recipes, employees) |
